# Stylio v1.0.0

**Released:** October 16, 2026<br>
**Platform:** browser and installable Progressive Web App (PWA)

[Open Stylio](https://wanthinnn.github.io/stylio/) · [Project README](../README.md)

Stylio's first public release brings on-device photo processing and an iPhone-
focused interface to the browser. It helps compatible photographs work with
Photographic Styles, Texture and Grain, and Portrait editing in Apple Photos.

## Photo processing

- Add Photographic Styles support to supported HEIC photographs from older
  iPhones, with Texture and Grain metadata for compatible iOS 27 Photos controls.
- Preserve existing native Styles and supported HDR, depth, thumbnail and face
  resources wherever the source and conversion route support them.
- Handle supported iPhone 16/17 native Styles contracts without replacing their
  original editing data unnecessarily. Includes the missing-tone-curve repair
  for the supported iOS 18 native Texture workflow.
- Import HEIC, JPEG, PNG and DNG. Additional raster formats are recognized when
  the browser and decoder support them. Raster/RAW conversion produces HEIC;
  DNG output is developed imagery, not an editable RAW file.
- Preserve compatible JPEG HDR gain maps through the supported HDR conversion
  path. Unsupported layouts produce an explanation rather than a silent promise
  of complete HDR compatibility.
- Pair supported HEIC and MOV resources for Live Photo export within a session.
- Retain source capture metadata, including dates and location where present,
  as part of the preservation workflow. Keep original files separately.

## Local AI tools

- **Lighting Depth Effect:** generate depth for supported photographs and export
  an editable Portrait-compatible HEIC with aperture and Portrait Lighting data.
- Preview Portrait blur, tap to change focus, and adjust aperture without
  rerunning depth inference for each adjustment. The preview approximates the
  effect; Apple Photos uses its own renderer.
- **Adaptive Styles:** analyze each photo locally and choose an editable Style
  starting point. Lite, Standard and Pro select different model/quality tiers.
- Automatically supplement missing Soft Skin/face data on supported outputs;
  preserve existing native data when it is already available.
- Use WebGPU acceleration where supported, with an explicit CPU/WASM selection
  for supported AI operations. Device, memory and browser capabilities matter.
- The **Sharpen Photo** setting supports local restoration when its separately
  provisioned model assets are available. These restoration weights are not
  automatically bundled into the public release; their upstream license and
  distribution restrictions still apply. An unavailable optional AI operation
  retains the normal processed result where supported.
- Download tools/models as needed and retain verified assets for reuse. Model
  downloads can be large, particularly for Standard and Pro.

## Apple photo compatibility

- Classify supported sources from their actual photo/container structure rather
  than relying on the displayed iOS version label.
- For eligible newer iPhone 16/17 editing contracts, create a separate Legacy
  Compatibility copy only when preflight checks establish that the change can
  be confined to supported editing metadata.
- Preserve protected image, HDR and depth resources during that conversion,
  with explicit checks on permitted changes and the completed output.
- When a newer contract cannot be interpreted safely, offer a preserved copy
  instead of attempting an unverified rebuild.
- Explain compatibility outcomes and any intentionally omitted editing metadata
  under **Details → Apple compatibility**.

This does not guarantee support for every future Apple photo format or every
Photos version. Import, editing, saving and reopening remain device-dependent.

## iPhone interface and app experience

- Four destinations: **Process, History, Guide and Settings**, with a separate
  History search action and support for returning to the previous screen.
- iPhone Home Screen installation guidance and a full-screen PWA experience.
- A floating glass toolbar with press, drag and release feedback; corrected dock
  placement across short and long screens and centered lenses on all four tabs.
- Stronger dark-mode glass with a visible material, directional highlights and
  light-through-background feedback. This is a web approximation of Liquid
  Glass, not the native UIKit optical renderer.
- Theme-aware launch artwork and a spinner whose size stays stable while styles
  load. Choose **Light, Dark or System** appearance.
- A compact AI Settings sheet with swipe dismissal, phone-specific outer corners,
  a centered privacy footer and the original switch/Model control dimensions.
- Grouped Settings and AI rows with trailing separator insets, plus Guide
  disclosure arrows positioned farther inside their cards.
- A visible animated update status immediately after choosing **Update Stylio**,
  remaining on screen until reload and recovering if the update check fails.
- English, Vietnamese and Simplified Chinese interfaces, with reduced-motion and
  high-contrast fallbacks for supported interface effects.

## History, queue and preferences

- Persist processed results and display-sized previews in local browser History,
  so they can be reopened and saved after a reload without reprocessing.
- Search History, inspect photo details, and share, download or delete a result.
- Show active and waiting photos in a shared queue. Processing is sequential by
  default; optional parallel processing uses two independent runtimes and may
  increase memory use, device temperature and battery consumption.
- Configure the default save action, result previews, original-format reminder
  and keep-screen-awake behavior where the browser supports it.
- Keep **Clear cache** separate from **Reset Stylio**: the former removes
  downloaded tools while preserving photos/preferences; reset also removes local
  History and app preferences. Browser storage can be unavailable or evicted.

## Privacy, offline use and practical limits

Photo processing and AI inference run on the device; the normal web workflow
does not upload photographs. Processed photos and previews remain in browser
storage until removed or evicted. The app still makes network requests to load
itself, download libraries/models and send the existing session visit-counter
ping. "On-device" does not mean there are no network requests.

The PWA caches its app shell for faster repeat launches and offline reuse.
Features whose tools/models have not been downloaded still need a connection;
offline behavior also depends on browser storage and operating-system eviction.
Serve the app over HTTPS or localhost. Some processing features require the
service worker's cross-origin isolation setup, supported WASM/WebGPU APIs and
sufficient memory. A browser tab cannot prevent iOS from suspending it.

Stylio remains experimental. Keep your originals and test exported copies in
Apple Photos before relying on their editability. It is independently developed
and is not affiliated with Apple.
